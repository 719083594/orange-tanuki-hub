# 私有音频验收

`scripts/verify-private-audio.mjs` 检查当前检出的源码能否读取既有音频数据集。它不会部署、合并代码、改变 Space、生成声音或修改原音频文件。需要 Node.js 24，不增加 npm 依赖。

## 运行条件

在已经安全配置好 `VOICE_HF_TOKEN`、数据集固定版本和多作品映射的私有测试环境运行。沿用[配置说明](configuration.md)中的 `VOICE_*` 变量和未跟踪的 `voice-datasets.json`；不要把 Token、真实映射或音频提交到公开仓库，也不要粘贴到聊天或命令历史中。

脚本启动当前源码的临时 HTTP 服务，地址只绑定 `127.0.0.1`，端口由系统分配。它使用独立临时缓存，正常结束或失败后关闭服务并清理该缓存，不读取或删除原 `VOICE_CACHE_DIR` 缓存。进程被强制终止时，系统临时目录中可能留下以 `orange-private-check-` 开头的目录，应由该私有环境的管理员按临时文件策略清理。

从项目根目录执行，适用于 **Bash / PowerShell / CMD**：

```text
node --env-file-if-exists=.env scripts/verify-private-audio.mjs
```

默认要求 5 个已配置作品全部 `ready`。可在私有环境设置 `VOICE_VERIFY_EXPECT_GAMES`（1–9）和可选 `VOICE_VERIFY_EXPECT_CLIPS`（预期索引总条目数）核对当前版本；期望数量应来自已核实的索引清单。未设置总条目数时，脚本只核对各接口统计是否一致，不证明外部清单完整。

## 检查内容与用量

- 所有已配置作品的索引加载、作品与角色数量、音频目录汇总。
- 每作品抽取首个角色的首种语言，检查片段第一页、第二页和越界空页；同时检查素材列表按作品分页。
- 每作品只读取 1 个 WAV 和其配对 TXT；验证 RIFF/WAVE 文件头、UTF-8 文本、长度和片段 ID。
- 对同一 WAV 检查 HEAD、206 分段读取和 416 越界响应，检查非法分页参数返回 400。
- 核对缓存容量和下载次数，避免额外音频预下载。

首次运行会下载全部配置索引以及每作品 1 个 WAV 和 1 个 TXT。音频文件上限仍由 `VOICE_MAX_FILE_BYTES` 限制（默认每个 64 MiB）；索引上限默认每源 256 MiB。超过限制、索引失败或任一检查失败时退出码为 1，不继续抽样后续作品。正常运行时每个作品最多下载两份媒体文件，缓存复用用于后续 HEAD 和 Range 请求。没有 GPU 或模型推理调用。

成功时输出一行 JSON，`ok` 为 `true`，包含作品数、总条目数、抽样数量和检查项；退出码为 0。失败时输出 `ok: false` 和固定的 `stage`（例如 `index_ready`、`expected_clip_count`、`wav`），退出码为 1。输出不包含 Token、映射、角色名、台词、私有路径或下载 URL。

这个结果只证明当前源码在当前环境中的索引与抽样 HTTP 数据验证通过。`listening_verified` 始终为 `false`：文件头和分段读取通过不等于浏览器已经解码、手机已经发声或人耳试听完成。随后仍需在受访问控制的测试页面分别验证电脑、手机播放、暂停、拖动进度、下载和台词配对；不得据此声称生产已发布。
